# Telemetry and health-label contract for review

| Stream or record | Event and identity | Availability, units and limitations |
| --- | --- | --- |
| cct.traces | Nested OTLP JSON resourceSpans/scopeSpans/spans. Resolve service.name from resource attributes. Deduplicate by run, traceId and spanId. | Integer-string start/end Unix ns. Record broker/consumer first-seen time separately. Application spans do not inherit the probe run ID automatically. Join the trace IDs in the archived shopping receipt or use an exclusive manifest interval with documented ambiguity for background traffic. |
| cct.metrics | Nested OTLP resourceMetrics/scopeMetrics/metrics. Identity includes resource, scope, metric, data point attributes, start time when provided, and timestamp. | Span counts/histograms are cumulative across the Collector process. Duration buckets use ms. Difference compatible points and detect resets. Pod readiness and total restarts per pod are observed gauges with unit 1. Unknown readiness is omitted. Store first-seen time and scrape/flush cadence. |
| cct.logs | Nested OTLP resourceLogs/scopeLogs/logRecords. Keep service.name, pod UID, cct.run_id, event enum, and cct.event_id. | timeUnixNano is the log timestamp. observedTimeUnixNano is when Merul's client read it. First availability in Spark may be later. A repeated identical event at the same timestamp uses an ordinal within the same source. Keep overlap boundaries on whole timestamps. |
| Shopping receipt | schema_version 1.0, run_id, request-level trace_id and UTC timestamps, expected edges, connected server records, bounded errors. | Jaeger start_us and duration_us are microseconds. observed_at is query time, an upper bound on when the records were first available. Do not use a post-run query as evidence of live warning lead time. |
| Missingness | Distinguish a service receiving no measured requests, a failed exporter, an absent metric target, and a missing parent. | Emit unknown/coverage fields. A returned HTTP 200 and a healthy pod do not establish a complete trace. |

## Proposed joint CCT-10 rule

Use UTC milliseconds for service windows. Window [start,end) has width 5,000 ms, aligned to epoch. Each row has run_id, service, start_ms, end_ms, available_ms, complete, ready, restart_delta, requests, errors and p95_ms. Ensure pod evidence is fresh for that window. A missing or distrusted observation remains unknown. Keep 30-second overview plots separate from the labeling cadence.

1. Split by entire run before fitting anything. From sufficiently sampled healthy training windows for each service, choose an initial latency limit of twice the median window p95. Mark services with insufficient training data uncalibrated. Tune on validation runs, record the final service-specific limits, sample minimum and software revision, then freeze. The candidate error-fraction limit is 5% with at least 20 requests per window. These are starting parameters awaiting team evaluation.
2. For a prediction cutoff, use only closed windows whose observations are available by the cutoff. Use the latest eligible revision for each window. Current unready state or a positive restart delta marks a service affected. Otherwise require two consecutive sufficiently sampled, complete windows with p95 above the service limit or error fraction at/above 5%. A single breach, low count, stale/missing data or missing previous breach remains unknown. A sufficiently observed window inside both limits is healthy. Run the executable rule at `observability.health.state`.
3. At event-time cutoff t, retain only facts available by t and store the actual emitted_at timestamp. At horizons 10, 30 and 60 s, evaluate newly affected services among those healthy at t. Exclude affected and unknown-at-cutoff services from the eligible denominator. If future observation coverage is insufficient, mark the label censored and report coverage. Score onset at or before emission as zero/negative warning time and report it separately. Keep finalized outcome labels separate from features available at t.
4. Compare persistence (predict no newly affected services) and reverse one-hop reachability from already affected services over the graph available at t. Score eligible sets per run with precision, recall, F1 and signed warning time. Report empty/empty matches separately from F1 on nonempty union. Also report missed and unobservable outcomes, effective fault time and healthy false alarms. Stratify by run, never split windows of one run across train/test. No labels are inferred from the synthetic phase name or the injected target.

Merul owns signal quality, units and availability. Mithil reviews the label and graph semantics. Param records durable ingestion times and deduplication. Komalika records effective fault and recovery intervals. Live threshold calibration and cross-owner review remain open.
